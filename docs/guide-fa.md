## ۱. DeTT&CT چیست و به چه دردی می‌خورد؟

DeTT&CT (مخفف *Detect Tactics, Techniques & Combat Threats*) ابزاری است برای تیم‌های آبی (Blue Team) و SOC که به این سؤال‌ها جواب می‌دهد:

- **چه چیزهایی را می‌بینیم؟** چه لاگ‌ها و منابع داده‌ای داریم و کیفیت آن‌ها چقدر است؟
- **چه چیزهایی را تشخیص می‌دهیم؟** برای کدام تکنیک‌های حمله، تشخیص (Detection) داریم و چقدر خوب است؟
- **کجا ضعف داریم؟** کدام تکنیک‌هایی که مهاجمان واقعی استفاده می‌کنند را نه می‌بینیم و نه تشخیص می‌دهیم؟
- **در طول زمان چقدر پیشرفت کرده‌ایم؟**

همه‌ی این‌ها بر پایه‌ی چارچوب **MITRE ATT&CK** است. نتیجه به شکل **نقشه‌ی حرارتی (Heat map)** در ATT&CK Navigator، فایل اکسل و نمودار ارائه می‌شود.

**جریان کلی کار:**

```
منابع داده (Data sources) ──► امتیاز Visibility ──► امتیاز Detection ──► مقایسه با گروه‌های تهدید
       │                            │                      │                         │
   کیفیت داده                 چه چیزی را می‌بینیم      چه چیزی را تشخیص می‌دهیم       کجا ضعف داریم
```

## ۲. مفاهیم پایه

### MITRE ATT&CK
ATT&CK یک پایگاه دانش از رفتار مهاجمان است و از این اجزا تشکیل شده:

| مفهوم | توضیح | مثال |
|---|---|---|
| **Tactic** (تاکتیک) | هدف مهاجم در یک مرحله | Credential Access |
| **Technique** (تکنیک) | روشی که برای رسیدن به هدف استفاده می‌شود | `T1003` OS Credential Dumping |
| **Sub-technique** | نوع دقیق‌تر یک تکنیک | `T1003.001` LSASS Memory |
| **Group** (گروه) | گروه‌های تهدید شناخته‌شده | `G0016` APT29 |
| **Campaign** (کمپین) | یک عملیات مشخص | `C0024` SolarWinds Compromise |
| **Software** | بدافزار یا ابزاری که گروه‌ها استفاده می‌کنند | `S0002` Mimikatz |
| **Data source** (منبع داده) | نوع داده‌ای که برای دیدن یک تکنیک لازم است | Process Creation |

### دامنه‌ها (Domain)
ATT&CK سه دامنه دارد و هر فایل DeTT&CT به یکی از آن‌ها تعلق دارد:

| دامنه | کاربرد |
|---|---|
| `enterprise-attack` | شبکه‌ها و سیستم‌های سازمانی: ویندوز، لینوکس، مک، ابر، کانتینر و... (رایج‌ترین) |
| `ics-attack` | سیستم‌های کنترل صنعتی (SCADA، PLC و...) |
| `mobile-attack` | دستگاه‌های موبایل (اندروید و iOS) |

### پلتفرم‌ها (Platform)
برای Enterprise: `Windows`، `Linux`، `macOS`، `PRE`، `Office Suite`، `Identity Provider`، `SaaS`، `IaaS`، `Network Devices`، `Containers`، `ESXi`. مقدار `all` یعنی همه‌ی پلتفرم‌ها.

### سه نوع فایل اصلی (YAML)
همه‌ی اطلاعات شما در سه نوع فایل YAML نگهداری می‌شود:

| نوع فایل | `file_type` | چه چیزی را نگه می‌دارد |
|---|---|---|
| منابع داده | `data-source-administration` | منابع داده‌ای که دارید، به تفکیک نوع سیستم، با امتیاز کیفیت |
| تکنیک‌ها | `technique-administration` | امتیاز Visibility و Detection برای هر تکنیک، همراه با تاریخچه |
| گروه‌ها | `group-administration` | گروه‌ها، کمپین‌ها یا سناریوهای دلخواه خودتان (مثلاً سناریوی رد تیم) |

### Visibility در برابر Detection
- **Visibility (دیدپذیری):** آیا داده‌ی لازم برای *دیدن* یک تکنیک را دارید؟ مثلاً اگر لاگ Process Creation دارید، اجرای PowerShell مخرب را *می‌بینید*.
- **Detection (تشخیص):** آیا یک *قانون یا هشدار* دارید که آن تکنیک را تشخیص بدهد و به تحلیل‌گر اطلاع بدهد؟

بدون Visibility نمی‌توان Detection ساخت. پس اول منابع داده را ثبت می‌کنید، بعد Visibility را بالا می‌برید و بعد Detection می‌سازید.

### Systems و Applicable to
محیط هر سازمانی یکدست نیست. ممکن است روی ایستگاه‌های کاری ویندوز EDR داشته باشید، ولی روی سرورهای لینوکس فقط لاگ پایه. DeTT&CT برای پوشش این تفاوت از دو مفهوم استفاده می‌کند:

- **System:** یک «نوع سیستم» در محیط شما که اسم دلخواه دارد و به پلتفرم‌های ATT&CK وصل می‌شود. مثلاً `Windows workstations` روی پلتفرم Windows، یا `Linux servers` روی Linux.
- **Applicable to:** هر ثبت منبع داده، یا هر امتیاز Visibility و Detection، مشخص می‌کند برای کدام System(ها) صدق می‌کند. مقدار `all` یعنی همه‌ی سیستم‌ها.

**مثال:** منبع داده‌ی *Process Creation* را دو بار ثبت می‌کنید:
- یک بار برای `Windows workstations` با محصول Sysmon و کیفیت ۴.
- یک بار برای `Linux servers` با محصول auditd و کیفیت ۲.

### جدول امتیازها

**کیفیت داده (Data quality)**، برای هر منبع داده از ۰ تا ۵ در پنج بُعد:

| بُعد | سؤالی که جواب می‌دهد |
|---|---|
| Device completeness | از چند درصد دستگاه‌ها این داده جمع می‌شود؟ |
| Data field completeness | آیا فیلدهای لازم (مثلاً command line یا parent process) در داده هست؟ |
| Timeliness | داده به‌موقع (نزدیک به زمان واقعی) می‌رسد؟ |
| Consistency | فیلدها استاندارد و یکدست هستند (مثلاً نام‌گذاری یکسان)؟ |
| Retention | داده به اندازه‌ی کافی نگهداری می‌شود؟ |

مقادیر: `0` هیچ، `1` ضعیف، `2` متوسط، `3` خوب، `4` خیلی خوب، `5` عالی. اگر همه‌ی ابعاد صفر باشند، منبع داده **غیرفعال** حساب می‌شود.

**امتیاز Visibility** (۰ تا ۴):

| امتیاز | معنی |
|---|---|
| 0 | هیچ: داده‌ای برای دیدن این تکنیک ندارید |
| 1 | حداقلی |
| 2 | متوسط |
| 3 | خوب |
| 4 | عالی: همه‌ی داده‌ی لازم با کیفیت خوب در دسترس است |

**امتیاز Detection** (منفی ۱ تا ۵):

| امتیاز | معنی |
|---|---|
| -1 | هیچ: تشخیصی وجود ندارد |
| 0 | فقط برای فارنزیک یا زمینه (Forensics / context): داده هست ولی هشدار نه |
| 1 | پایه (Basic) |
| 2 | متوسط (Fair) |
| 3 | خوب (Good) |
| 4 | خیلی خوب (Very good) |
| 5 | عالی (Excellent): تشخیص دقیق، کم‌خطا و تست‌شده |

**Visibility خودکار:** وقتی DeTT&CT امتیاز Visibility را از منابع داده می‌سازد، این‌طور حساب می‌کند. اول می‌بیند یک تکنیک در ATT&CK به چند منبع داده نیاز دارد، بعد بررسی می‌کند چند درصدشان را دارید:

| درصد منابع داده‌ی موجود | امتیاز Visibility |
|---|---|
| ۰٪ | 0 |
| ۱ تا ۴۹٪ | 1 |
| ۵۰ تا ۷۴٪ | 2 |
| ۷۵ تا ۹۹٪ | 3 |
| ۱۰۰٪ | 4 |

این امتیازها با علامت `auto_generated: true` ذخیره می‌شوند. اگر امتیازی را دستی تغییر بدهید، این علامت `false` می‌شود و DeTT&CT در به‌روزرسانی‌های بعدی بدون اجازه‌ی شما آن را عوض نمی‌کند.

### Score logbook (تاریخچه‌ی امتیاز)
هر امتیاز Visibility و Detection یک **تاریخچه** دارد که هر ردیفش شامل تاریخ، امتیاز و توضیح است. امتیاز «فعلی» همیشه جدیدترین ردیف است. با این تاریخچه می‌توانید پیشرفت را در طول زمان نشان بدهید (نمودار Graph).

## ۳. نصب، اجرا و تنظیمات اولیه

### پیش‌نیاز
- Python نسخه‌ی 3.10 یا بالاتر
- Git

### نصب

```
git clone https://github.com/st0p3r/dettect.git
cd dettect
python3 -m venv venv
source venv/bin/activate          # در ویندوز: venv\Scripts\activate
pip install -r requirements.txt
```

### اجرا

```
python dettect.py editor
```

مرورگر آدرس `http://localhost:8080` را باز می‌کند. گزینه‌های مفید:

| گزینه | کاربرد |
|---|---|
| `-p 9000` | اجرا روی پورت دیگر (اگر 8080 اشغال است) |
| `--no-browser` | مرورگر خودکار باز نشود |
| `--host 0.0.0.0` | دسترسی از کامپیوترهای دیگر شبکه. **احتیاط:** رابط وب احراز هویت ندارد و هر کسی در شبکه به فایل‌ها دسترسی پیدا می‌کند. |

برای متوقف کردن، در ترمینال `Ctrl+C` بزنید.

### اجرا با Docker

```
docker build -t dettect .
docker run -p 8080:8080 dettect
```

### اولین کارها بعد از اجرا
1. **داده‌ی ATT&CK را دانلود کنید:** به **Settings** بروید و **Download ATT&CK data** را بزنید. این کار یک بار انجام می‌شود و بعد از آن برنامه بدون اینترنت هم کار می‌کند. اگر انجامش ندهید، برنامه هر بار داده را از سرور MITRE می‌گیرد که ممکن است در دسترس نباشد.
2. **فایل‌های نمونه را اضافه کنید:** در **Dashboard** دکمه‌ی **Add sample files** را بزنید تا با داده‌ی آماده کار را یاد بگیرید.

### پوشه‌ها

| پوشه | محتوا |
|---|---|
| `input/` | فایل‌های YAML شما (همان «My files» در رابط وب) |
| `output/` | خروجی‌ها: لایه‌های Navigator، اکسل، نمودار و YAMLهای ساخته‌شده |
| `stix-data/` | داده‌ی ATT&CK دانلودشده |
| `cache/` | کش داده‌ی ATT&CK (اگر از سرور آنلاین استفاده کنید) |
| `sample-data/` | فایل‌های نمونه |

**نکته‌ی مهم:** پوشه‌ی `input/` جزو Git نیست، پس از فایل‌های خودتان جداگانه نسخه‌ی پشتیبان بگیرید.

## ۴. آشنایی با رابط وب

منوی سمت چپ چهار بخش دارد:

| بخش | صفحه‌ها | کاربرد |
|---|---|---|
| **Overview** | Dashboard، Files | نمای کلی و مدیریت فایل‌ها |
| **Administration** | Data sources، Techniques، Groups | ویرایش فایل‌های YAML (ورود اطلاعات) |
| **Analysis** | Data source mapping، Visibility coverage، Detection coverage، Threat groups، ATT&CK statistics | ساخت خروجی و تحلیل |
| **System** | Jobs، Settings | تاریخچه‌ی اجراها و تنظیمات |

- دکمه‌ی ماه یا خورشید بالای صفحه حالت تاریک و روشن را عوض می‌کند.
- کنار بیشتر فیلدها یک آیکون **؟** هست. اگر نشانگر ماوس را رویش ببرید، توضیح کوتاهی نشان می‌دهد.
- رابط وب روی موبایل هم کار می‌کند (منو با دکمه‌ی ☰ باز می‌شود).

## ۵. داشبورد (Dashboard)

**چه چیزی نشان می‌دهد:**
- تعداد فایل‌های منبع داده، تکنیک، گروه و خروجی. با کلیک روی هر کارت به بخش مربوطه می‌روید.
- **Workflow:** چهار قدم اصلی کار با DeTT&CT، با دکمه‌ی Edit برای رفتن به ادیتور و Analyze برای رفتن به صفحه‌ی تحلیل.
- **Recent jobs:** آخرین اجراها و وضعیتشان.
- نسخه‌ی DeTT&CT و ATT&CK و منبع داده‌ی ATT&CK (آنلاین یا محلی).
- اگر از سرور آنلاین MITRE استفاده می‌کنید، یک هشدار زرد پیشنهاد می‌دهد داده را دانلود کنید.

**کاربرد:** نقطه‌ی شروع روزانه. برای کاربر تازه‌کار، دکمه‌ی **Add sample files** بهترین راه شروع است.

## ۶. مدیریت فایل‌ها (Files)

این صفحه سه تب دارد:

### تب My files
فایل‌های YAML شما (پوشه‌ی `input/`). برای هر فایل نوع، نام، دامنه، نسخه، حجم و تاریخ تغییر نمایش داده می‌شود.

| عمل | توضیح |
|---|---|
| **Upload** | بارگذاری یک یا چند فایل از کامپیوتر. می‌توانید فایل را مستقیم روی صفحه بکشید و رها کنید. |
| **New file** | ساخت فایل خالی جدید از هر سه نوع |
| 👁 View | دیدن محتوای فایل |
| ✏️ Edit | باز کردن فایل در ادیتور مناسب |
| ⬇ Download | دانلود به کامپیوتر |
| ⋯ ← Rename | تغییر نام |
| ⋯ ← Duplicate | ساخت کپی. قبل از تغییرات بزرگ، یک کپی پشتیبان بسازید. |
| ⋯ ← Delete | حذف دائمی (غیرقابل برگشت) |

### تب Output
همه‌ی چیزهایی که DeTT&CT می‌سازد:

| نوع | پسوند | کاربرد |
|---|---|---|
| Navigator layer | `.json` | نقشه‌ی حرارتی برای ATT&CK Navigator |
| Excel | `.xlsx` | جدول کامل برای گزارش و بررسی |
| Graph | `.html` | نمودار تعاملی پیشرفت در طول زمان |
| YAML | `.yaml` | فایل تکنیک ساخته‌شده از منابع داده |

برای YAMLهای خروجی، دکمه‌ی **Copy to my files** فایل را به `input/` کپی می‌کند تا بتوانید ویرایشش کنید و در تحلیل‌ها به کارش ببرید.

### تب Samples
فایل‌های نمونه‌ی آماده. با **Add to my files** به فایل‌های شما اضافه می‌شوند.

## ۷. ادیتور منابع داده (Data sources)

**هدف:** ثبت اینکه چه منابع داده‌ای (لاگ‌ها) دارید، روی کدام سیستم‌ها، با کدام محصول و با چه کیفیتی.

### نوار ابزار بالای همه‌ی ادیتورها
این نوار در هر سه ادیتور یکسان است:

| دکمه | کاربرد |
|---|---|
| **Open** | باز کردن یکی از فایل‌های شما، یا گزینه‌ی *Open from computer* برای باز کردن مستقیم از کامپیوتر |
| **New** | فایل جدید |
| ⬇ | دانلود فایل فعلی (حتی بدون ذخیره) |
| **Save as** | ذخیره با نام جدید |
| **Save** | ذخیره در My files |
| **Health check** | بررسی خطاهای فایل توسط DeTT&CT |
| **Analyze** | رفتن مستقیم به صفحه‌ی تحلیل همین فایل |

- برچسب زرد **unsaved changes** یعنی تغییرات ذخیره نشده‌اند. اگر بخواهید صفحه را ترک کنید، برنامه هشدار می‌دهد.
- اگر فایل هنگام باز شدن ایراد داشته باشد (مثلاً پلتفرم نامعتبر یا مقدار گم‌شده)، ادیتور آن را **تعمیر** می‌کند و فهرست تغییرات را در یک کادر زرد نشان می‌دهد.

### File details (مشخصات فایل)
روی **File details** کلیک کنید تا باز شود:
- **Name:** نام فایل. در نام لایه‌ها و خروجی‌ها هم استفاده می‌شود.
- **ATT&CK domain:** دامنه. فقط وقتی فایل خالی است قابل تغییر است.
- **Notes:** یادداشت آزاد.
- **Systems:** تعریف انواع سیستم‌های محیط شما. هر سیستم یک نام (applicable to) و یک یا چند پلتفرم دارد.
  - مثال: `Windows workstations` روی Windows، `Linux servers` روی Linux، `Cloud` روی IaaS و SaaS.
  - اگر نام یک سیستم را عوض کنید، در همه‌ی منابع داده هم عوض می‌شود.
  - اگر سیستمی را حذف کنید، از منابع داده هم حذف می‌شود.

### فهرست منابع داده (سمت چپ)
- **Add data source:** جستجو در منابع داده‌ی ATT&CK. فقط منابعی پیشنهاد می‌شوند که با پلتفرم‌های سیستم‌های شما سازگارند. منابع ویژه‌ی DeTT&CT هم هستند، مثل `Web [DeTT&CT data source]`، `Email`، `DHCP` و `Internal DNS`.
- **Add all:** همه‌ی منابع داده‌ی مرتبط با پلتفرم‌هایتان را یکجا اضافه می‌کند (با کیفیت صفر). این روش برای شروع یک ارزیابی کامل مفید است، چون بعد فقط باید امتیاز موارد موجود را بدهید.
- **جستجو** روی نام، سیستم و محصول کار می‌کند.
- نقطه‌ی سبز یعنی فعال (کیفیت بیشتر از صفر). نقطه‌ی خاکستری یعنی غیرفعال.
- حذف با آیکون سطل انجام می‌شود و دکمه‌ی **Undo** در پیام پایین صفحه آن را برمی‌گرداند.

### جزئیات منبع داده (سمت راست)
هر منبع داده یک یا چند **ثبت (Registration)** دارد که هر کدام برای یک یا چند System است:

| فیلد | توضیح |
|---|---|
| **Applicable to** | این ثبت برای کدام سیستم‌هاست. `all` یعنی همه و با مقدار دیگری ترکیب نمی‌شود. اگر مقداری در Systems تعریف نشده باشد، قرمز می‌شود. |
| **Date registered** | تاریخ ثبت در این فایل |
| **Date connected** | تاریخی که داده به SIEM یا Data lake متصل شد. در نمودار پیشرفت استفاده می‌شود. |
| **Data source enabled** | خاموش کردنش همه‌ی امتیازهای کیفیت را صفر می‌کند و روشن کردنش مقادیر قبلی را برمی‌گرداند. |
| **Available for data analytics** | آیا داده در جای مرکزی (مثل SIEM) برای تحلیل و تشخیص در دسترس است؟ |
| **Products** | محصولاتی که این داده را می‌دهند، مثل `Sysmon`، `Microsoft Defender for Endpoint` یا `auditd` |
| **Comment** | توضیح آزاد |
| **Data quality** | پنج بُعد کیفیت، هر کدام ۰ تا ۵ (جدول بخش ۲) |
| **Custom key-value pairs** | فیلدهای دلخواه، مثلاً `owner: SOC-team` یا `cost: high`. در جستجوی EQL هم قابل استفاده‌اند. |

دکمه‌ی **Add registration for other system(s)** یک ثبت جدید برای سیستم‌های دیگر اضافه می‌کند.

**نمونه:**
> منبع داده‌ی **Process Creation**:
> - ثبت ۱: Applicable to = `Windows workstations`، Products = `Sysmon`، Date connected = 2024-03-10، کیفیت: 4، 4، 3، 4، 3
> - ثبت ۲: Applicable to = `Linux servers`، Products = `auditd`، کیفیت: 2، 2، 3، 2، 2

## ۸. ادیتور تکنیک‌ها (Techniques)

**هدف:** ثبت امتیاز Visibility و Detection برای هر تکنیک ATT&CK، به تفکیک سیستم، همراه با تاریخچه.

### File details
- **Name**، **Domain** و **Notes** مثل ادیتور منابع داده‌اند.
- **Platforms:** پلتفرم‌هایی که این فایل پوشش می‌دهد. پیشنهاد تکنیک‌ها بر اساس همین پلتفرم‌ها فیلتر می‌شود.

**توصیه:** معمولاً فایل تکنیک را دستی شروع نمی‌کنید. آن را از منابع داده می‌سازید (بخش ۱۰، گزینه‌ی *Technique administration YAML*)، بعد با **Copy to my files** به فایل‌هایتان می‌آورید و اینجا Detectionها را اضافه می‌کنید.

### فهرست تکنیک‌ها
- **Add technique:** جستجو با شناسه یا نام (مثلاً `T1059` یا `PowerShell`). می‌توانید شناسه را دستی هم تایپ کنید.
- کنار هر تکنیک دو برچسب هست: **V** برای بیشترین امتیاز Visibility و **D** برای بیشترین امتیاز Detection. علامت `D–` یعنی Detection ندارد (‎-1). رنگ برچسب‌ها از خاکستری (کم) تا سبز (زیاد) است.

### جزئیات تکنیک
بالای جزئیات، شناسه و نام تکنیک، پلتفرم‌ها و لینک صفحه‌ی آن در سایت ATT&CK نمایش داده می‌شود. زیر آن دو بخش **Detection** و **Visibility** هست که هر کدام یک یا چند «شیء امتیاز» دارند:

| فیلد | توضیح |
|---|---|
| **Applicable to** | این امتیاز برای کدام سیستم‌هاست. در Visibility، مقدار `all` با مقدار دیگری ترکیب نمی‌شود. اگر همان سیستم در دو شیء تکرار شود، قرمز می‌شود. |
| **Location** (فقط Detection) | محل تشخیص، مثلاً نام Rule، SIEM یا EDR. پیشوندی مثل `EDR: Rule 1` باعث می‌شود گزینه‌ی *Count detections* تشخیص‌ها را دسته‌بندی کند. |
| **Comment** | توضیح |
| **Current score** | امتیاز فعلی. تغییرش جدیدترین ردیف تاریخچه را عوض می‌کند و اگر تاریخ نداشته باشد، تاریخ امروز را می‌گذارد. |
| **Score logbook** | تاریخچه‌ی کامل امتیاز: تاریخ، امتیاز، توضیح و در Visibility سوئیچ `auto` |
| **New score entry** | یک ردیف جدید با تاریخ امروز اضافه می‌کند تا تغییر امتیاز در تاریخچه ثبت شود. |
| **Custom key-value pairs** | فیلدهای دلخواه |

**بهترین روش ثبت تغییرات:** وقتی امتیازی بهتر شد (مثلاً یک Rule جدید نوشتید)، به‌جای تغییر Current score، دکمه‌ی **New score entry** را بزنید و امتیاز جدید را در ردیف جدید بگذارید. این‌طوری نمودار پیشرفت درست نمایش داده می‌شود.

**نمونه:**
> تکنیک **T1003.001 LSASS Memory**:
> - Detection برای `Windows workstations`: Location = `EDR: Credential theft rule`، امتیاز 4
> - Detection برای `Windows servers`: Location = `SIEM: Sysmon EID 10 on lsass`، امتیاز 2
> - Visibility برای `all`: امتیاز 3 (auto_generated)

## ۹. ادیتور گروه‌ها (Groups)

**هدف:** تعریف گروه‌های تهدید، کمپین‌ها یا سناریوهای دلخواه به شکل فهرستی از تکنیک‌ها و نرم‌افزارها. وقتی گروه مورد نظرتان در ATT&CK نیست، یا اطلاعات اختصاصی‌تری دارید، از این ادیتور استفاده کنید.

**کاربردها:**
- گروه تهدیدی که در گزارش‌های Threat Intelligence خودتان یا گزارش‌های داخلی منطقه دیده‌اید ولی در ATT&CK نیست
- سناریوی رد تیم یا تست نفوذ
- یک حادثه‌ی امنیتی واقعی که در سازمان رخ داده
- «گروه» ترکیبی از تهدیدهای مرتبط با صنعت شما

### فیلدها
| فیلد | توضیح |
|---|---|
| **Group name** | نام گروه |
| **Campaign** | اختیاری. ترکیب نام گروه و کمپین باید یکتا باشد، پس یک گروه می‌تواند چند کمپین داشته باشد. |
| **Enabled** | فقط گروه‌های فعال در تحلیل استفاده می‌شوند. |
| **Techniques** | فهرست تکنیک‌ها با جستجوی ATT&CK. حداقل یک تکنیک لازم است. |
| **Software** | نرم‌افزارهای ATT&CK (مثل `S0002 Mimikatz`). در تحلیل، تکنیک‌های این نرم‌افزارها هم قابل افزودن‌اند. |
| **Custom key-value pairs** | فیلدهای دلخواه، مثلاً منبع گزارش |

در **File details** پلتفرم‌ها را انتخاب کنید. پیشنهادها بر اساس آن فیلتر می‌شوند.

## ۱۰. تحلیل منابع داده (Data source mapping)

**ورودی:** یک فایل منابع داده.

### خروجی‌ها (می‌توانید چندتا را همزمان انتخاب کنید)

| خروجی | چه می‌سازد | کاربرد |
|---|---|---|
| **Navigator layer** | نقشه‌ی حرارتی: هر تکنیک بر اساس درصد منابع داده‌ی موجود رنگ می‌گیرد. | دیدن اینکه منابع داده‌ی فعلی چه بخشی از ATT&CK را پوشش می‌دهند |
| **Excel** | فهرست کامل منابع داده با جزئیات و کیفیت | گزارش، بررسی با تیم و پیدا کردن منابع با کیفیت پایین |
| **Graph** | نمودار تعداد منابع داده‌ی متصل‌شده در طول زمان (بر اساس *Date connected*) | نشان دادن پیشرفت به مدیریت |
| **Technique administration YAML** | فایل تکنیک جدید با امتیاز Visibility خودکار | **شروع فایل تکنیک**. گزینه‌ی *Include all ATT&CK techniques* همه‌ی تکنیک‌های پلتفرم را اضافه می‌کند، حتی آن‌هایی که امتیاز صفر دارند. |
| **Update visibility scores** | امتیاز Visibility یک فایل تکنیک موجود را بر اساس تغییرات منابع داده به‌روز می‌کند | بعد از اضافه شدن منبع داده‌ی جدید یا به‌روزرسانی ATT&CK. قبل از تغییر، یک نسخه‌ی پشتیبان (`_backup_N.yaml`) ساخته می‌شود. |

**سؤال‌های تعاملی در Update:** DeTT&CT ممکن است بپرسد که آیا توضیحی برای امتیازهای جدید وارد می‌کنید، یا آیا یک امتیاز دستی جایگزین شود. سؤال در یک کادر بنفش زیر خروجی ظاهر می‌شود و با دکمه‌ها جواب می‌دهید (Yes، No، Yes to ALL، No to ALL، Continue). برای جواب متنی، مثل متن توضیح، از کادر پایین استفاده کنید.

### فیلترها
- **Only include systems (applicable to):** تحلیل فقط برای سیستم‌های خاص. مثلاً فقط `Windows workstations`.
- **EQL search:** فیلتر پیشرفته (بخش ۱۵). مثلاً فقط منابعی که محصولشان Sysmon است.

### Advanced options (در همه‌ی صفحه‌های تحلیل)
| گزینه | توضیح |
|---|---|
| Output filename | نام فایل خروجی. اگر خالی بماند، خودکار ساخته می‌شود. |
| Layer name | نام لایه در Navigator |
| Navigator layer settings | تنظیمات نمایش لایه: `layout` (side/flat/mini)، `showAggregateScores`، `showMetadata`، `includeTactic`، `includeAttackVersion` |
| Overwrite existing output files | به‌جای ساخت `_1` و `_2`، فایل قبلی بازنویسی شود. |
| Show detailed health check errors | جزئیات خطاهای فایل نمایش داده شود. |

## ۱۱. پوشش Visibility و Detection (Coverage)

دو صفحه‌ی **Visibility coverage** و **Detection coverage** تقریباً مثل هم‌اند. **ورودی** هر دو یک فایل تکنیک است.

### خروجی‌ها
| خروجی | Visibility coverage | Detection coverage |
|---|---|---|
| **Layer** | نقشه‌ی امتیاز Visibility | نقشه‌ی امتیاز Detection |
| **Overlay** | Visibility و Detection روی هم | Detection و Visibility روی هم |
| **Graph** | پیشرفت Visibility در طول زمان | پیشرفت Detection در طول زمان |
| **Excel** | همه‌ی تکنیک‌ها با امتیازها | همه‌ی تکنیک‌ها با امتیازها |

**Overlay چه چیزی را نشان می‌دهد؟** رنگ‌ها چهار وضعیت را از هم جدا می‌کنند:
- هم Visibility دارید هم Detection: وضعیت خوب.
- Visibility دارید ولی Detection ندارید: **فرصت!** داده هست و فقط Rule باید نوشت.
- Detection دارید ولی Visibility ثبت نشده: احتمالاً فایل ناقص است.
- هیچ‌کدام: ضعف.

### گزینه‌ها
- **Platforms:** محدود کردن به پلتفرم‌های خاص. پیش‌فرض، پلتفرم‌های داخل فایل است.
- **EQL search on visibility / detection:** فیلتر روی امتیازها (بخش ۱۵).
- **Search all scores in the score logbook:** به‌طور پیش‌فرض فقط جدیدترین امتیاز در جستجو بررسی می‌شود. با این گزینه کل تاریخچه بررسی می‌شود.
- **Count detections:** در توضیحات لایه به‌جای فهرست محل‌ها، تعداد تشخیص‌ها به تفکیک پیشوند (`EDR:`، `SIEM:` و...) نشان داده می‌شود.

## ۱۲. گروه‌های تهدید (Threat groups)

**هدف:** ساخت نقشه‌ی حرارتی از رفتار گروه‌های تهدید، مقایسه‌ی گروه‌ها با هم، یا مقایسه‌ی آن‌ها با پوشش خودتان. این مهم‌ترین بخش برای **دفاع مبتنی بر تهدید (Threat-informed defense)** است.

### گزینه‌ها
| گزینه | توضیح |
|---|---|
| **Groups** | گروه‌های ATT&CK با شناسه، نام یا نام مستعار (مثلاً `APT29`، `G0016` یا `Cozy Bear`)، یا فایل گروه خودتان. اگر هیچ گروه و کمپینی انتخاب نشود، **همه‌ی گروه‌ها** استفاده می‌شوند. |
| **Campaigns** | کمپین‌های ATT&CK. مکمل گروه‌هاست. |
| **ATT&CK domain** | دامنه. اگر فایل گروه دامنه داشته باشد، نادیده گرفته می‌شود. |
| **Platforms** | محدود کردن به پلتفرم‌ها |
| **Overlay** | مقایسه با: **Groups** (گروه‌های دیگر)، **Campaigns**، **Visibility** یا **Detection** (یک فایل تکنیک) |
| **Software** | *Ignore*: نرم‌افزارها نادیده گرفته شوند. *Add*: تکنیک‌های نرم‌افزارها علامت بخورند ولی در امتیاز حساب نشوند. *Include*: در امتیاز هم حساب شوند. |

### نتیجه چه معنایی دارد؟
- **بدون Overlay:** امتیاز هر تکنیک برابر تعداد گروه‌هایی است که از آن استفاده می‌کنند. تکنیک‌های پررنگ‌تر یعنی محبوب‌تر بین مهاجمان.
- **Overlay با گروه:** رنگ‌ها نشان می‌دهند هر تکنیک فقط در گروه اول، فقط در گروه دوم یا در هر دو استفاده شده.
- **Overlay با Visibility یا Detection:** نشان می‌دهد کدام تکنیک‌های این گروه را پوشش می‌دهید و کدام را نه. این **دقیق‌ترین خروجی برای اولویت‌بندی** است.

## ۱۳. آمار ATT&CK (ATT&CK statistics)

اطلاعات عمومی ATT&CK که مستقل از فایل‌های شماست:

| گزینه | خروجی | کاربرد |
|---|---|---|

## ۱۴. Jobها، خروجی‌ها و ATT&CK Navigator

### Job
هر تحلیل یک **Job** است. پنل Job این بخش‌ها را دارد:
- **وضعیت:** Queued (در صف)، Running (در حال اجرا)، Finished (تمام شده)، Failed (خطا) یا Cancelled (لغو شده). Jobها یکی‌یکی اجرا می‌شوند.
- **دستور معادل** خط فرمان، با دکمه‌ی کپی
- **کنسول** با خروجی زنده
- **سؤال‌ها** با دکمه‌های جواب
- دکمه‌ی **Stop** برای توقف
- **Created / changed files:** فایل‌هایی که ساخته یا تغییر داده شدند، با دکمه‌های View، Navigator، Download و Copy to my files

صفحه‌ی **Jobs** تاریخچه‌ی همه‌ی اجراها را تا ری‌استارت شدن برنامه نگه می‌دارد.

### دیدن لایه‌ها
**داخل برنامه (View):** یک پیش‌نمایش سریع از نقشه‌ی حرارتی، با راهنمای رنگ‌ها (Legend) و تعداد هر رنگ. اگر نشانگر ماوس را روی هر تکنیک ببرید، جزئیاتش را می‌بینید. تب JSON هم محتوای خام لایه را نشان می‌دهد.

**ATT&CK Navigator (دکمه‌ی Navigator):** نمای کامل ماتریس ATT&CK در سایت MITRE باز می‌شود.
- مرورگر ممکن است اجازه‌ی دسترسی به «شبکه‌ی محلی» یا «برنامه‌های این دستگاه» را بپرسد. باید **Allow** را بزنید.
- اگر کار نکرد، فایل را دانلود کنید و در Navigator از مسیر **Open Existing Layer ← Upload from local** بازش کنید.
- در Navigator می‌توانید لایه‌ها را با هم ترکیب کنید، به صورت تصویر یا اکسل خروجی بگیرید و فیلتر کنید.

**Graph:** نمودار تعاملی داخل خود صفحه نمایش داده می‌شود.

## ۱۵. جستجو با EQL

EQL (Event Query Language) فیلتر پیشرفته‌ای است که در سه جا کار می‌کند. هر کدام ساختار خودش را دارد.

### منابع داده (در صفحه‌ی Data source mapping)
ساختار: `data_sources where <شرط>`

فیلدهای قابل استفاده: `data_source_name`، `applicable_to`، `products`، `available_for_data_analytics`، `comment`، `data_quality.device_completeness`، `data_quality.data_field_completeness`، `data_quality.timeliness`، `data_quality.consistency`، `data_quality.retention` و فیلدهای سفارشی شما.

```
data_sources where arrayContains(products, "Sysmon")
data_sources where available_for_data_analytics == true
data_sources where data_quality.device_completeness >= 3
data_sources where data_source_name == "Process*"
data_sources where applicable_to == "Windows workstations"
```

### Visibility و Detection (در صفحه‌های Coverage و Threat groups)
ساختار: `techniques where <شرط>`

فیلدها: `technique_id`، `technique_name`، و برای Visibility: `visibility.applicable_to`، `visibility.comment`، `visibility.score_logbook.score`، `visibility.score_logbook.date`، `visibility.score_logbook.comment`، `visibility.score_logbook.auto_generated`. برای Detection همین‌ها با `detection.` به‌جای `visibility.`، به‌علاوه‌ی `detection.location`.

```
techniques where visibility.score_logbook.score >= 3
techniques where detection.score_logbook.score >= 2
techniques where arrayContains(detection.location, "EDR")
techniques where arraySearch(detection.location, loc, loc == "Splunk*")
techniques where detection.score_logbook.date >= "2024-01-01"
techniques where technique_id == "T1003*"
techniques where arrayContains(visibility.applicable_to, "all")
```

**نکته‌ها:**
- `*` جای هر متنی می‌نشیند. مثلاً `"T1003*"` همه‌ی زیرتکنیک‌های T1003 را شامل می‌شود.
- برای فیلدهای فهرستی (مثل `products`، `location` و `applicable_to` در تکنیک‌ها) از `arrayContains` استفاده کنید. این تابع فقط مقدار دقیق را پیدا می‌کند. برای جستجو با `*` از `arraySearch` استفاده کنید، مثلاً `arraySearch(detection.location, loc, loc == "EDR*")`.
- برای ترکیب شرط‌ها از `and`، `or` و `not` استفاده کنید.
- اگر اسم فیلد اشتباه باشد، DeTT&CT در کنسول خطا می‌دهد و فهرست فیلدهای مجاز (schema) را نشان می‌دهد.
- به‌طور پیش‌فرض فقط جدیدترین امتیاز تاریخچه بررسی می‌شود. برای بررسی کل تاریخچه، گزینه‌ی *Search all scores* را روشن کنید.

**کاربردها:**
- لایه‌ای فقط از Detectionهای EDR، برای مقایسه با Detectionهای SIEM
- لایه‌ای فقط از Detectionهای اضافه‌شده در سال جاری، برای گزارش سالانه
- فقط Visibilityهای خوب (۳ و بالاتر)، برای پیدا کردن جاهایی که آماده‌ی نوشتن Rule هستند

## ۱۶. تنظیمات (Settings)

### ATT&CK data source
- **MITRE's TAXII server:** داده از سرور آنلاین MITRE گرفته و ۳۰ روز کش می‌شود. نیاز به دسترسی به `attack-taxii.mitre.org` دارد.
- **Local STIX data:** داده از فایل‌های روی همین کامپیوتر خوانده می‌شود. بدون اینترنت کار می‌کند و نسخه‌ی ATT&CK ثابت می‌ماند. **این گزینه توصیه می‌شود.**
- **Ignore TLS verification errors:** فقط وقتی یک پروکسی ترافیک TLS را باز می‌کند و اتصال خطای گواهی می‌دهد. از نظر امنیتی توصیه نمی‌شود.

### Download ATT&CK data
داده‌ی ATT&CK (حدود ۶۵ مگابایت) را از GitHub در پوشه‌ی `stix-data/` دانلود می‌کند و تنظیمات را خودکار روی Local می‌گذارد. هر چند ماه یک بار (بعد از انتشار نسخه‌ی جدید ATT&CK) دوباره دانلود کنید.

### Cache
داده‌ی ATT&CK پردازش‌شده کش می‌شود. اگر داده‌ی جدید دانلود کردید یا نتایج عجیب بود، **Clear cache** را بزنید.

### About
نسخه‌ی DeTT&CT، ATT&CK، Navigator و نسخه‌ی فرمت فایل‌ها.

## ۱۷. سناریوهای کاربردی (Use Cases)

### سناریو ۱: ارزیابی اولیه‌ی بلوغ SOC
**سؤال:** «الان چه چیزی را می‌بینیم و تشخیص می‌دهیم؟»

1. **Data sources ← New.** در File details سیستم‌ها را تعریف کنید (مثلاً Windows workstations، Windows servers، Linux servers، Cloud).
2. **Add all** را بزنید تا همه‌ی منابع داده‌ی مرتبط اضافه شوند.
3. برای هر منبع داده‌ای که واقعاً دارید، محصول، تاریخ اتصال و کیفیت را وارد کنید. بقیه را صفر بگذارید یا حذف کنید.
4. **Save** و بعد **Analyze**. خروجی‌های **Navigator layer**، **Excel** و **Technique administration YAML** را بسازید.
5. YAML تکنیک ساخته‌شده را با **Copy to my files** به فایل‌هایتان بیاورید.
6. در **Techniques**، برای تکنیک‌هایی که Rule یا Use case دارید، Detection وارد کنید.
7. در **Detection coverage**، خروجی **Overlay with visibility** بسازید و در Navigator ببینید.

**نتیجه:** تصویری روشن از وضعیت فعلی که برای گزارش به مدیریت قابل ارائه است.

### سناریو ۲: تحلیل شکاف بر اساس تهدیدهای مرتبط (Gap analysis)
**سؤال:** «در برابر گروه‌هایی که صنعت ما را هدف می‌گیرند، کجا ضعف داریم؟»

1. گروه‌های مرتبط با صنعت یا منطقه‌تان را از گزارش‌های Threat Intelligence پیدا کنید.
2. **Threat groups:** آن گروه‌ها را اضافه کنید، Overlay را روی **Detection** بگذارید و فایل تکنیک خودتان را انتخاب کنید.
3. خروجی را در Navigator ببینید. تکنیک‌هایی که گروه‌ها استفاده می‌کنند ولی Detection ندارید، **اولویت اول** شما هستند.
4. همین کار را با Overlay روی **Visibility** هم انجام دهید. جاهایی که Visibility هم ندارید، به لاگ جدید نیاز دارند.

### سناریو ۳: اولویت‌بندی جمع‌آوری لاگ
**سؤال:** «بودجه‌ی محدود داریم. اول کدام لاگ را جمع کنیم؟»

1. **ATT&CK statistics ← Data source statistics** با پلتفرم‌های خودتان. منابع داده‌ای که بیشترین تکنیک را پوشش می‌دهند، در بالای فهرست هستند.
2. این فهرست را با اکسل منابع داده‌ی خودتان (بخش ۱۰) مقایسه کنید.
3. **ترکیب با تهدید:** در **Threat groups** لایه‌ی گروه‌های مرتبط را بسازید و ببینید پرتکرارترین تکنیک‌هایشان به کدام منابع داده نیاز دارند (در Navigator یا صفحه‌ی تکنیک در سایت ATT&CK).
4. بعد از اضافه شدن لاگ جدید، آن را در **Data sources** ثبت کنید و با **Update visibility scores** فایل تکنیک را به‌روز کنید.

### سناریو ۴: برنامه‌ریزی رد تیم و پرپل تیم (Red / Purple team)
**سؤال:** «تمرین بعدی را روی چه چیزی متمرکز کنیم؟ و نتیجه را چطور ثبت کنیم؟»

1. **Groups ← New:** سناریوی تمرین را به شکل یک گروه با تکنیک‌هایش تعریف کنید (مثلاً «Red team – Ransomware scenario»).
2. **Threat groups:** گروه را از فایل خودتان انتخاب کنید و Overlay را روی **Detection** بگذارید. خروجی پیش‌بینی می‌کند کدام مراحل سناریو احتمالاً تشخیص داده نمی‌شوند.
3. بعد از تمرین، نتیجه‌ی واقعی را در **Techniques** ثبت کنید. با **New score entry** و توضیح، مثلاً «Purple team 2025-Q1: detected by EDR».
4. تمرین‌های بعدی را به‌عنوان کمپین جدید (فیلد Campaign) در همان گروه اضافه کنید تا تاریخچه بماند.

### سناریو ۵: پیگیری پیشرفت و گزارش دوره‌ای
**سؤال:** «در شش ماه گذشته چقدر بهتر شده‌ایم؟»

1. هر تغییر امتیاز را با **New score entry** و تاریخ درست ثبت کنید، نه با تغییر امتیاز قبلی.
2. **Detection coverage ← Graph** و **Visibility coverage ← Graph:** نمودار پیشرفت در طول زمان.
3. **Data source mapping ← Graph:** نمودار رشد منابع داده (بر اساس Date connected).
4. با EQL، لایه‌ای فقط از تغییرات اخیر بسازید: `techniques where detection.score_logbook.date >= "2025-01-01"`.

### سناریو ۶: مقایسه‌ی محیط‌ها یا ابزارها
**سؤال:** «پوشش EDR ما در برابر SIEM چطور است؟» یا «ویندوز در برابر لینوکس؟»

- **بر اساس ابزار:** در Location تشخیص‌ها از پیشوند استفاده کنید (`EDR: ...`، `SIEM: ...`). بعد دو لایه با EQL بسازید و در Navigator مقایسه کنید:
  - `techniques where arraySearch(detection.location, loc, loc == "EDR*")`
  - `techniques where arraySearch(detection.location, loc, loc == "SIEM*")`
- **بر اساس سیستم:** در Data source mapping با فیلتر **Only include systems** برای هر سیستم یک لایه‌ی جدا بسازید.

### سناریو ۷: مقایسه‌ی گروه‌های تهدید با هم
**سؤال:** «دو گروه تهدید چه تکنیک‌های مشترکی دارند؟»

**Threat groups:** گروه اول را در Groups بگذارید، Overlay را روی **Groups** و گروه دوم را در Overlay. تکنیک‌های مشترک رنگ جداگانه می‌گیرند. Detection برای این تکنیک‌ها، در برابر هر دو گروه محافظت می‌کند.

### سناریو ۸: به‌روز ماندن با ATT&CK
**سؤال:** «MITRE نسخه‌ی جدید داده. چه چیزی برای ما تغییر کرده؟»

1. **Settings ← Download ATT&CK data** (نسخه‌ی جدید) و بعد **Clear cache**.
2. **ATT&CK statistics ← ATT&CK updates** برای تکنیک‌ها: تغییرات اخیر را ببینید و Detectionهای مرتبط را بازبینی کنید.
3. **Data source mapping ← Update visibility scores:** امتیازهای Visibility بر اساس تغییرات ATT&CK به‌روز می‌شوند.
4. **Health check** روی فایل‌ها، برای پیدا کردن تکنیک‌های حذف‌شده یا تغییرکرده.

## ۱۸. عیب‌یابی

| مشکل | علت و راه‌حل |
|---|---|
| `address already in use` | پورت اشغال است. از `python dettect.py editor -p 9000` استفاده کنید. |
| `Cannot connect to MITRE's CTI TAXII server` یا خطای 503 | سرور MITRE در دسترس نیست. در **Settings** داده را دانلود کنید و Local را انتخاب کنید. |
| Navigator می‌گوید `ERROR retrieving layer` | در پیام مرورگر **Allow** را بزنید. اگر قبلاً Block کرده‌اید، در تنظیمات سایت `mitre-attack.github.io` اجازه را عوض کنید. راه دیگر: فایل را دانلود کنید و در Navigator با Upload from local بازش کنید. |
| فایل در ادیتور باز نمی‌شود و درباره‌ی version خطا می‌دهد | نسخه‌ی فایل قدیمی است. روی فایل **Health check** بزنید (یا هر تحلیلی را اجرا کنید). DeTT&CT پیشنهاد ارتقا می‌دهد که باید با **Yes** جواب بدهید. |
| خطای EQL و نمایش schema | اسم فیلد یا ساختار اشتباه است. بخش ۱۵ و فهرست فیلدها در خروجی را ببینید. برای تکنیک‌ها از `techniques where` استفاده کنید، نه `visibility where`. |
| `The search returned 0 ...` | جستجوی EQL نتیجه‌ای نداشت. شرط را ساده‌تر کنید. |
| گروهی در پیشنهادهای Threat groups نیست | داده‌ی ATT&CK بارگذاری نشده است (هشدار زرد بالای صفحه). Settings را بررسی کنید. می‌توانید نام گروه را دستی هم تایپ کنید. |
| تغییرات ادیتور در تحلیل دیده نمی‌شود | فایل را **Save** کنید. تحلیل روی نسخه‌ی ذخیره‌شده در My files اجرا می‌شود. |
| Job گیر کرده و جلو نمی‌رود | احتمالاً منتظر جواب یک سؤال است. پایین کنسول را ببینید، یا Job را با **Stop** متوقف کنید. |

## ۱۹. پیوست: معادل خط فرمان

هر کاری که در رابط وب می‌کنید، یک دستور خط فرمان معادل دارد که در پنل Job نشان داده می‌شود. این برای خودکارسازی (مثلاً با cron) مفید است:

```
# منابع داده: لایه، اکسل، نمودار و YAML تکنیک
python dettect.py ds -fd input/data-sources.yaml -l -e -g -y

# به‌روزرسانی امتیاز Visibility
python dettect.py ds -fd input/data-sources.yaml -ft input/techniques.yaml -u

# Visibility: لایه و Overlay با Detection
python dettect.py v -ft input/techniques.yaml -l -o

# Detection: لایه، نمودار و اکسل
python dettect.py d -ft input/techniques.yaml -l -g -e

# گروه‌ها: APT29 در مقایسه با Detection شما
python dettect.py g -g APT29 -o input/techniques.yaml -t detection

# آمار منابع داده برای ویندوز
python dettect.py ge -ds enterprise -p Windows

# بررسی سلامت فایل
python dettect.py v -ft input/techniques.yaml --health

# استفاده از داده‌ی ATT&CK محلی
python dettect.py v -ft input/techniques.yaml -l --local-stix-path stix-data
```

راهنمای هر حالت: `python dettect.py <mode> --help`، مثلاً `python dettect.py ds --help`.
